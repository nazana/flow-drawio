# flow2 대비 누락 기능과 작업 순서

## 현재 남은 작업 — 2026-09-30 갱신

이 요약은 아래 초기 누락 목록 및 과거 진행 기록보다 우선한다.

- **10번 링크: 구현됨, 사용자 테스트 후 개선 예정.** 사용자가 동작/사용감이 이상하다고 보고했으나 구체적 재현 조건은 아직 없음. 지금 추가 수정하지 않고 사용자가 테스트하며 제시하는 사례에 따라 개선한다. 완료 확정으로 취급하지 않는다.
- **11번 가져오기: 구현·검증 완료.** JSON 미리보기, 시스템·도형·I/F 선택 병합, 중복 유지/변경/새 코드, 의존 정의 자동 포함, 단일 실행 취소. 이전 전용 레인과 다른 저장소 링크는 미리보기에서 제외 안내.
- **12번 관계/문제 탐색: 구현·검증 완료.** 보기 메뉴의 연결 관계 강조, 경고 클릭으로 해당 도형·선 선택 및 이동. 강조는 원본 스타일에 저장하지 않는다.
- **13번 출력: 구현·검증 완료.** 내보내기에서 현재 페이지 PNG/SVG/PPTX. PPTX는 16:9 슬라이드에 이미지 한 장, PNG·SVG는 draw.io 로컬 렌더러 사용. 도형별 편집 가능한 PPTX 및 전체 페이지 일괄 출력은 범위 밖.
- **전체 개조 이후:** PowerPoint 도형·연결선·텍스트를 개별 편집할 수 있는 PPTX 출력. 현재 이미지 출력은 임시 수준이며 사용자 핵심 요구는 편집 가능한 출력이다.
- **화면 통합:** draw.io 내부와 외부의 중복 패널·도구, 여백·색·글꼴 및 공간 배분 정리.
- **마지막 초기 화면:** 시작 화면·새 문서 생성 흐름과 샘플 선택을 함께 정의한다.
- **후속:** 폴더 구조로 문서 묶음 관리. 공용 표현/범례 정의의 문서 간 재사용은 범위를 다시 정할 후속 후보.
- **후속: 바이브 기반 초안 생성.** 자연어로 시스템·전문·순서·조건을 입력 → 구조 미리보기 → 사용자 확인 → 편집 가능한 draw.io 초안 생성. 폐쇄망 실행 방식과 모델 선택은 도입 시 정한다.
- **장기 구상:** 공장 전체 시스템·설비·I/F 통합 연결도는 별도 과제.
- **생략:** 8번 전용 스윔레인/컨테이너 소속 연동. 9번 별도 그룹/메모 구현. 기본 표·컨테이너·그룹·메모 사용. 샘플만 마지막 단계로 이동.

## 작업 진행 규칙 (사용자 요청)

- 각 항목을 시작하기 전에 목적, 화면에서 바뀌는 동작, 작업 범위와 확인 방법을 설명하고 사용자의 명시적인 확인을 받는다.
- 확인된 항목만 구현한다. 다음 항목으로 자동 진행하지 않는다.
- 1번은 앞선 턴에서 코드가 추가됐지만 사용자 확인 및 브라우저 동작 확인 전이다. 완료로 확정하지 않고, 아래 범위 제안에 대한 확인부터 받는다. 기존 코드는 임의로 되돌리지 않는다.
- 이번 갱신은 할 일 문서만 변경하며 기능 구현은 진행하지 않는다.

## 이미 있는 것

도형·연결선 기본 편집은 draw.io가 담당한다. 시스템/I/F 정의 추가·수정, 도형에 시스템 지정, 선에 기존 I/F 지정, 전체 그림과 속성 수동 저장·재조회, .drawio 반입·반출, revision 저장 충돌 차단은 현재 앱에 있다. 송수신 불일치는 경고만 표시한다. draw.io의 그룹·스윔레인과 우리 속성을 함께 사용하는 복합 동작은 아직 회귀 검증하지 않았다.

## 1번 시작 전 확인받을 범위

목적: 그림을 보면서 I/F 목록을 한눈에 찾고 수정할 수 있게 한다.

1. 캔버스 아래 표에 I/F 코드·이름·종류·채널·송신·수신·포맷을 표시한다.
2. 검색과 열별 정렬, 표 접기/펼치기를 제공한다.
3. 표의 연결선 버튼을 누르면 현재 페이지의 해당 선을 선택하고 속성을 표시한다. 같은 I/F를 쓰는 선이 여러 개면 각각 선택한다.
4. 그림에서 선을 선택하면 해당 I/F 행을 강조한다.
5. 표의 수정 버튼으로 기존 정의 수정 창을 연다.
6. 확인 후 위 동작과 정의 수정 후 저장·재열기를 점검하고, 발견한 문제를 보완한다.

현재 페이지를 넘는 연결선 탐색, 열 너비 수동 조절, 자동 범례, 화면 전체 디자인 통합은 이 항목에 포함하지 않는 제안이다. 사용자 확인 전 추가 구현·검증을 시작하지 않는다.

앞선 설명을 정정한다: flow2의 **시스템 레인**에서는 위치에 따라 시스템 소속이 갱신된다. **자유 레인**은 소속을 바꾸지 않는다. 또한 초기 연결 모달 방식은 최신 코드에서 선 생성 후 I/F를 지정하는 흐름으로 바뀌었다. 초기 README 설명보다 뒤쪽 변경 기록과 현재 코드를 우선한다.

## 1번 현재 코드 상태 — 사용자 확인 대기

- 캔버스 아래 I/F 표를 추가했다. 현재 문서의 정의 전체를 보여준다.
- 코드·이름·종류·채널·송수신·포맷으로 검색하고 각 열 제목으로 오름/내림차순 정렬한다.
- 같은 I/F를 쓰는 선이 여러 개면 각각 선택 버튼을 제공한다. 현재 페이지에 선이 없으면 ‘없음’을 표시한다.
- 그림에서 선택한 선에 대응하는 행과 연결선 버튼을 강조한다. 여러 선을 선택하면 해당 행들을 모두 강조한다.
- 수정 버튼은 기존 I/F 수정 창을 사용한다. 별도 데이터 복사본을 만들지 않아 패널과 표가 같은 정의를 표시한다.
- 표 접기/펼치기로 캔버스 공간을 확보한다.

구현: src/InterfaceTable.tsx, src/App.tsx, src/style.css. TypeScript 검사와 production 빌드 통과. 이번 단계의 브라우저 조작 테스트는 수행하지 않았다.


## 1번 사용자 확인 후 변경 (2026-09-29)

사용자 승인: 최초 선택은 초기 표시 설정에만 쓰고, I/F 목록은 언제든 열고 닫는다.

- 새 문서 창에서 업무 흐름 / 인터페이스 흐름 / 빈 그림을 선택한다. 모두 빈 그림에서 시작한다. 인터페이스 흐름만 I/F 표를 처음부터 표시한다.
- 상단 `I/F 목록` 버튼으로 표시·숨김을 전환한다. 숨기기는 시스템/I/F 데이터나 그림을 변경하지 않는다.
- 같은 브라우저의 localStorage에 문서 ID별 표시 상태를 즉시 기억한다. 서버 저장 버튼과 별개이며, 다른 브라우저/기기로 동기화하지 않는다.
- 기존 문서·가져온 파일에 표시 설정이 없으면 I/F 정의가 있는 문서는 표시, 없는 문서는 숨김으로 시작하고 그 상태를 기억한다.
- 표 내부 ‘숨기기’도 상단 버튼과 같은 설정을 변경한다. 문서 전환 시 검색·정렬은 초기화된다.
- TypeScript 검사와 production 빌드 통과. 이번 변경의 브라우저 동작 테스트는 수행하지 않았다.
- 2번 및 설정/범례/디자인 통합은 아직 시작하지 않았다. 각각 설명 및 확인 후 진행한다.


## 2번 구현 및 확인 (2026-09-29)

사용자 확인 범위: 선을 자유롭게 만들고 선택한 선에 기존/새 I/F를 지정한다. 노드는 업무 지점이며 시스템 소속은 선택 정보다. 소속 반영 옵션과 노드 시스템명 표시 설정을 함께 구현했다.

- 연결선 속성에서 `새 I/F 만들기`: 연결된 두 노드의 소속을 기본값으로 채우며, 소속이 없으면 송수신을 직접 선택한다. 등록된 시스템이 아예 없으면 시스템 탭에서 먼저 등록하도록 안내한다.
- 새 정의 등록·선 지정·선택한 노드 소속 변경을 draw.io 모델 트랜잭션 하나로 묶었다. 취소는 그림을 변경하지 않는다. 실행 취소 한 번으로 함께 복원된다.
- 기존 I/F 지정에도 `송수신 정보를 도형의 소속에도 적용` 옵션을 제공한다. 기본은 꺼짐이다. 옵션을 켜면 기존→새 시스템을 표시한다.
- 기존 소속과 송수신이 다르면 조용히 덮어쓰지 않고 적용을 거부한다. 소속 없는 노드는 허용하며 미지정 자체를 불일치로 경고하지 않는다. 다른 연결선에 생긴 실제 불일치는 경고한다.
- 상단 `보기 → 노드 시스템명 표시`로 라벨 아래 시스템 코드·이름을 표시/숨김한다. 업무 이름 원본은 그대로 유지한다.
- 표시 설정은 첫 페이지 root의 `flowShowSystems`에 저장되어 문서 저장 및 .drawio 반입·반출에 포함된다. 인터페이스 흐름 신규 문서는 켜짐, 업무 흐름/빈 그림은 꺼짐이다. 속성이 없는 기존 문서는 꺼짐으로 연다.
- 시스템명은 Flow Studio 브리지의 표시 기능이다. 일반 draw.io에서 파일을 열 때 동일한 표시를 보장하지 않는다. PNG/SVG/PPTX 출력 통합은 13번에서 다룬다.

- 폴더는 태그와 별도 계층으로 관리: 폴더 id/parentId/name, 문서는 folderId로 소속 참조. 문서당 한 폴더, 태그는 여러 개. 기존 문서는 미분류에서 시작.
- 폴더 이동은 문서 ID와 버전 이력을 유지하는 정리 작업. 버전 복원이 과거 폴더 위치로 이동시키지 않도록 문서 내용과 분리.
- 폴더 기능 구현 시 하위 폴더 순환 방지, 이름 중복 범위, 폴더 삭제 시 문서 보존 및 이동 규칙, 서버 검색/페이지 처리를 함께 구현. 현재는 UI 자리나 미사용 DB 열을 추가하지 않음.

### 8번 방향 재검토: 컨테이너 중심
- 사용자가 기본 컨테이너를 발견하고 스윔레인의 필요성을 재검토함. 다음 범위 제안은 draw.io 기본 컨테이너를 우선 사용.
- 일반 컨테이너는 묶음만, 시스템을 지정한 컨테이너는 내부 노드 소속 연동 후보. 스윔레인 전용 UI는 추가하지 않음.
- 구현 전 중첩 컨테이너, 들어가기/빠져나오기, 기존 소속 덮어쓰기와 I/F 비교 선택창 연동을 설명하고 확정한다.
